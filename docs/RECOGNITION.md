# 路径识别流水线

核心输入是应用提供的目录快照，不读取媒体文件、不访问文件系统或 TMDB。流程为：

```mermaid
flowchart LR
  A[完整目录树的视频路径] --> B[分词脚本]
  B --> C[词语与相邻词标注]
  C --> T[保留歧义的片名候选]
  T --> D[目录级季集与片名建议]
  D --> E[每个目标文件的建议 Metadata 与依据]
  E --> F[保存轻量目录快照]
  F --> G[用户主动搜索并确认作品与季集]
  G --> H[organizer 预览和执行]
```

配置只有一种格式：`{tokenizer, annotators, resolver}`。分词和建议各一条启用的脚本，建议阶段继续使用 resolver 契约；标注可启停、增删，支持脚本或正则；普通标注先执行、片名标注最后执行，两组内分别按 `order` 排序。同一棵树开始执行时固定一份配置快照。保存失败不会替换正在生效的配置。

## 结构与阶段边界

三个阶段均使用同步入口 `function extract(ctx)`，通过返回 JSON 数据提供结果。输入递归冻结。分词与标注不能写最终 Metadata。

分词输入 `ctx.file={fileId,path,directory}`、`ctx.sources[]`、`ctx.params`。来源包含 `id/kind/text/depth`；文件名不含扩展名，父目录近到远，不包含解析边界本身及其父级。分词返回：

```js
[{id: 't0', sourceId: 'name', parentId: null, kind: 'text', text: 'Show', start: 0, end: 4}]
```

`kind` 为 `text/number/separator/group`。保留原文、分组、数字、分隔符与 UTF-16 位置，不预设“是否季号／集号”。同层不得重叠，顶层须覆盖全部原文，范围不得切开代理对。默认脚本将连续汉字（含辅助平面汉字）、英文字母 `A–Z/a–z` 和数字 `0–9` 组成一个词，其他字符作为分隔点。纯数字词使用 `number`，其他词使用 `text`。`第3集`、`HD1080P`、`S01E03` 保持完整，`H.264` 则为两个词；分隔符保留原文，括号保留嵌套分组。规则脚本可修改。

标注输入 `ctx.file`、`sources`、`tokens`、`candidates`、`params`。`source=filename/directories/all` 决定可见来源；已有候选只包含完整落在所选来源内的项。规则 `target` 指定候选身份，`order` 是唯一非负整数。脚本返回：

```js
function extract(ctx) {
  return ctx.tokens.filter(t => t.kind === 'text').flatMap(token =>
    reFindAll('(?i)S([0-9]+)', token.text).map(match => ({
      value: Number(match.groups[1]),
      spans: [{sourceId: token.sourceId, start: token.start + match.start,
        end: token.start + match.end}],
      strength: 'explicit', status: 'valid', reason: 'S 季标记'
    })))
}
```

宿主填写候选 `id/ruleId/role`。`strength` 为 `explicit/contextual/heuristic`；`status` 为 `valid/invalid`，均须填写依据。冲突与非法显式写法保留为候选，`valid` 仅表示值合法，不表示最终采纳。候选身份和最终元数据均仅包含 `tmdbId/title/mediaType/year/season/episodes` 六项。默认 TMDB、季号、年份和集数脚本各自读取原文及分词，不读取其他候选；片名最后消费全部标注。单词可有多个标签，也可标注词内子范围。宿主只校验类型、数值、范围和引用，TMDB 与季集等范围冲突由可编辑裁决脚本处理。未提供技术或发布组标注，`HD1080P/AAC/GROUP` 等文字保留为普通正文，不增加隐藏清洗。

正则规则使用 Go RE2，配置为 `{pattern,capture}`（命名捕获组）或 `{pattern,value}`（固定 JSON 值）。正则仅对所选来源的 `text/number` 词逐个匹配，不匹配分隔符或整组文本，跨词格式使用脚本。每次命中生成显式候选，位置映射回来源原文；捕获值由对应身份转换、校验。不存在来源清理、覆盖开关或字段直接写入接口。

默认片名标注排除其他元信息候选占用的范围（包括无效元信息标记），但保留合法推测集数占用的文字，从连续剩余区段生成基础片名候选，不在首个季集或年份处整体截断。相邻词统一用一个空格连接，标点不进入片名；已标注范围和括号组边界会分开候选，不跨来源拼接。同一来源有可用括号外正文时使用正文，否则按括号组分别提取；未标注的数字片名仍可保留。未增加类别、版本说明、来源署名等身份，因此未知说明文字仍可能成为片名候选。

裁决输入 `ctx.contextRoot/sourceBoundary/tree/files/targetFileIds/params`。`files[]` 提供整个上下文目录及子目录中每个文件的来源、片段、候选；`tree[]` 节点为 `path/parent/fileIds`。返回目标文件结果数组：

```js
[{fileId: 'file-0', metadata: {
  tmdbId: null, title: 'Show', mediaType: 'tv', year: null,
  season: 2, episodes: [3]
}, decisions: {
  title: {candidates: [{fileId:'file-0', candidateId:'title:0'}], reason:'片名候选'},
  season: {candidates: [{fileId:'file-0', candidateId:'season:0'}], reason:'显式季号'},
  episodes: {candidates: [{fileId:'file-0', candidateId:'episodes:0'}], reason:'显式集号'},
  mediaType: {candidates: [{fileId:'file-0', candidateId:'season:0'}], reason:'季号提供剧集依据'}
}}]
```

必须覆盖全部目标，不能增加或重复文件。Metadata 必须提供完整六个字段，未知标量为 `null`、未知集数为 `[]`，0 是有效季集号。所有非空字段需要依据；引用可跨文件，但必须指向当前树中有效候选。最终路径由宿主填写。

默认集数脚本保留明确季集格式；推测数字仅来自独立数字词，以及明确季标记后紧邻的数字。`第一季03` 保持原词，季号标注引用“第一季”，集数推测引用“03”；`作品1/HD1080P/H264/07v2` 不生成推测集数。候选引用完整数字串，超长数字不截取，年份范围不生成推测候选。普通标注执行顺序不改变默认候选解释。

默认裁决集中处理范围冲突：TMDB 范围中的数字不得采纳为季集；明确季集优先于重叠年份，`S01E01` 可同时支持季号与集数；季号及年份占用范围不用于推测集数。候选不删除，依据按强度、来源深度、原文位置及规则／候选 ID 稳定排序。

目录比较按直接父目录和文件名结构建立索引，不依赖最终片名。待比较集数替换为占位符，仅规范化明确季标记；其他正文、固定数字、技术文字和括号结构均保留。明确季号或 TMDB ID 不同的文件分开比较；身份未知的文件仅在组内身份唯一时与明确身份文件共同参与，不能连接不同作品或季。

推测集数必须有目录佐证：同组存在明确季号或集号依据，至少两个不同文件提供不同集数值，且当前文件只有一个满足条件的数字位置。单个文件即使存在季号也不确定裸数字集数；“作品1、作品2”的词内数字不生成推测候选，保留数字片名。支持缺集和重复发布，不按排序位置生成集号；相同集数的多个发布版本不能提供不同集数佐证。无效显式集号阻止推测接管。

确定集数后，裁决从基础片名候选的原文范围排除被采纳集数，重新提取连续区段，仍不跨元信息间隔、括号或来源拼接。未采纳数字留在片名中。最终片名沿用显式依据、较近来源和目录片名匹配的选择顺序；基础候选不被修改。派生片名同时引用原片名候选和采纳集数的依据，目录推断引用其他文件的数字候选及明确季集依据，均可从历史重建。没有季集依据时不推断电影。

## 目录范围与更新

应用先完成扫描再执行三阶段。导入目录时纳入其全部后代视频；导入单个文件时读取父目录整棵树作为上下文，只更新导入文件。重叠根折叠到外层，互不相交的根分别裁决。隐藏文件、符号链接和目标目录沿用 scanner 的排除规则；每棵树超过 2000 个视频直接报错，不截断。

选择性重新识别读取相同的完整上下文，仅检查点写入选中行。未选中、已提交文件和人工决定保持原业务语义；取消、中断后的重新识别标记继续用于重试。导入、重新识别和重试仅使用本地规则，不要求 Token、不创建 TMDB 客户端。matching 只在用户选择作品后查询详情及校验季集；organizer 仅接受用户确认或未变化登记的最终作品与季集。

## 用户确认

resolver 返回的六字段 Metadata 与 decisions 仅为建议。新文件无论明确格式或匹配强度均不自动确认；工作区不保存自动 TMDB 作品候选，entry 只保存用户草稿或确认结果；主动搜索结果由选择作品面板管理。唯一常规季仅作预填建议，校验不自动补季号。

工作区通过 candidates 接口读取既有轨迹的 sources、candidates 和建议，不重新运行脚本。用户可接受建议、选择同规则／来源／位置序号的候选，或点击原文连续 ASCII 数字，以相同来源和数字序号批量取数。原文取数用非数字区段数组保留结构，缺来源、数字个数或结构不符时留待修正；支持整数偏移和逐行手填合并集，不按排序补号。

确认接口校验文件身份、大小、修改时间、引用、取数值及 TMDB 季集，原子写入每文件 Confirmation；普通更新只保存草稿，不能授予确认。Confirmation 保存确认来源、时间、文件快照、最终作品与季集以及 EpisodeBasis，mtime 用纳秒字符串。修改作品或季集撤销确认；移组、执行勾选不撤销。相同文件重新识别仅更新建议，文件变化后保留人工草稿并撤销确认。未变化的已有登记从本地映射和已确认作品快照复用 registration 确认，不补查 TMDB。作品快照与视频检查点和媒体映射同事务保存，提交成功后才能释放写占用。

## 运行与历史

- 每条源码最多 32 KiB；分词与标注每次 250 ms，裁决 5 s。每文件最多 1024 片段、分组深度 16；每条标注最多 512 候选、每文件最多 1024 候选。
- 普通阶段输入／输出 4 MiB，裁决输入 64 MiB、输出 16 MiB；返回 JSON 的深度最多 12、集合最多 10000、字符串最多 32 KiB。领域限制另行校验。
- 可用 `trace/print/reSearch/reFindAll/reSub`；普通识别不收集事件，调试和样例的事件保留阶段、源码行列和诊断。每次调用最多 128 条事件及一条截断说明。输入输出自动日志只保存摘要，结果记录在阶段输出中。
- 脚本没有模块加载、网络、文件、系统命令或环境变量接口。goja 的执行中断不等于进程级内存隔离。
- 分词或裁决失败终止该树；标注失败继续收集诊断，整树不更新元数据。取消停止后续执行，保留已完成轨迹。observer 失败立即停止。

服务启动和规则保存时一次编译脚本、正则，严格解析参数与固定输出值，预计算规则摘要；执行期间只读取当前引擎，不逐文件重新解析配置。输入由显式转换器构造原生 JavaScript 对象和数组，按旧 JSON 输入的字段顺序、`null`、Unicode 和数字语义逐层冻结；冻结函数在用户代码执行前捕获，特殊属性名作为自有数据属性处理，不暴露 Go 反射对象。字节计数保留原输入大小限制。返回值仍在超时保护内有界读取，再直接转换为领域类型，继续校验未知字段、数值、六字段完整性、UTF-16 范围和跨文件引用。

普通识别在固定文件身份与路径顺序后，最多使用 `min(4, GOMAXPROCS, 文件数)` 个 worker。每个文件依次完成分词、普通标注和片名标注，每次脚本调用创建独立运行时；共享的只有不可变编译结果与配置。协调端按路径顺序合并候选、诊断并串行提交进度，全部文件成功后整树建议脚本只运行一次。标注错误继续收集且不生成整树建议；分词失败停止新派发并取消后续文件，保留先于失败文件的有序结果；取消等待活动 worker 退出。调试及带 Observer 的执行保持串行，复用同一文件处理核心，步骤顺序与即时停止行为不变。

正式执行每棵树共享一个 traceId，保存 Snapshot：context、tree、documents（来源、分词、候选）、files（建议及跨文件引用）、pipeline、digest 和必要的 diagnostics。普通执行不构造 Step、Before/After、Attempt 或 ScriptEvent；调试和样例通过同一执行核心按需捕获完整步骤。候选接口直接读取已提交快照，不从步骤重建。

快照及终态同事务提交，保存失败时工作区不得引用该快照。工作区或确认依据引用的历史不可清理；取消、中断和写入失败保留重试能力，重启将遗留运行摘要标记中断，不重置用户数据。识别进度按十个目标更新摘要，不增加编辑 revision；开始新一轮清空旧计数，工作区成功保存后才显示完成。历史展示候选、建议、依据和规则快照；执行过程、日志和源码事件定位仅在调试页提供。

执行器改进适用于所有已保存规则。新版默认脚本优化字符分类与调用内索引，仍完整提供可编辑 JavaScript；只用于新配置或主动“恢复默认规则 → 保存”，不覆盖已有源码。

存储格式为 7。旧格式直接拒绝，应用不会迁移、删除或重建已有数据库。验证与基准使用独立临时目录。

## 编辑与验证

规则页按“分词／候选标注／建议脚本”排列；普通标注与片名标注各自在组内排序；片名始终最后执行。新增规则或修改身份时进入对应组。单规则页试跑和保存使用“当前流水线＋草稿”。调试输入多行虚拟路径，不访问文件系统；结果按文件展示元数据、候选、原文范围、分词和跨文件依据。历史使用同样的结果组件。

规则样例使用 `{paths,root,targets,expected}`，运行完整流水线。分词／标注比较该规则按文件排列的输出数组；裁决比较完整文件结果。任何执行错误使样例失败。保存前必须通过当前草稿的全部样例。

根目录 tests/ 包含优化前冻结的 106 组完整候选／建议／引用基准（115 个文件），在 1／4 worker 和完整调试下比较既有源码与新版默认脚本；另含输入冻结、运行时隔离、字节计数、并行错误顺序和取消回归。还包括 100 个全部通过的路径样本，以及按词分隔、词内标注、正文中文集号、连续剩余片名区段、用户长路径、截图、目录佐证、清晰数字位置、数字片名、多个变化位置、派生片名、多作品、多季、多发布、选择性更新、边界、运行限制、持久化与重启测试。`make check` 运行完整验证；`BenchmarkRecognition2000/LightImport` 测量整树轻量执行及关系快照持久化，`FullDebug` 测量同一批路径的完整调试及 JSON 响应；两者分别记录耗时、累计分配和各自输出量。
